# Prepared native root records (W05 in progress)

The concrete `effect_prepare!` plan/prepare/admit path compiles native Future layouts and uses startup `SlotPool` root/output records and frame storage. Admission obtains the actual record, start/pending/completion/store cells and every factory/driver/callback/loss/output handle, then calls the explicit fallible `reserve(&Arc<R>, &PreparedRunContext<A,E>)` storage contract and owns its returned non-Clone resource bundle before invoking the factory. The native body receives `(Arc<R>, PreparedRunContext<A,E>, bundle)`; data/foreign-resource storage is not merely checked or acquired after its business prefix. Refusal rolls the complete vector back. Both factory and reservation captures, plus the actual owned bundle in Start, appear in typed layouts. Refusal is a Rust `Result<_, MemoryError>` outside business E, including E=!. Records are generation-checked/retired by the existing pool and cannot recycle while any context, output, cancellation observer or pending continuation owns them.

The prepared callback receives a non-Clone `PreparedRunContext<A,E>`. Checked copies use `try_clone`; ordinary `NativeContext: Clone` and System execution remain unchanged. No transparent strict support for arbitrary NativeContext-typed cloning callbacks is asserted. The concrete contract now declares `contexts` (including the root), `listeners`, `bridges`, and `clock_ticks` per context. Each retained root owns its complete startup-provisioned private domain: context and listener records, two clock batches per context, and a fixed destruction queue. Checked child/protected/parallel admission leases those actual records before a child factory can run. Private node references retain cancellation/clock parents and generation identities; zero-reference nodes clear outside gates before reuse. Child and parallel clock frontiers are independent; protected contexts mask parent cancellation and retain the caller's frontier. Same-root parallel cancellation selection is an alias of the supplied origin: requesting parallel cancels that source and its siblings/descendants, while child requests remain local. Failure flags and frontiers remain independent. Cross-root parallel selection and child inheritance retain a typed source context in an actually reserved RuntimeFrame, with a physically reserved source listener and target notification frame. `protected_from` retains a foreign clock source while masking its cancellation. Same-root paths keep owned generation-bearing node references. Bridge budget provisions separate source-owner and notification lanes, each with one actual cell per maximum remote link, private to each retained root row (clock-only does not lease notification storage). Returning a notification cannot bypass the source-owner quota; cancellation links also consume the source's declared listener budget. Source listener and every source/target/terminal owner are acquired before child dispatch, with transactional rollback. Notify and foreign parent cleanup use the existing intrusive prepared drain, not recursively nested cross-root callbacks or late clones. The source capture drops/unregisters before its terminal target guard allows node reuse. Root re-admission checks old bridge cells have physically returned. Closing uses a dedicated per-node clock loan bit so source-frontier acknowledgment cannot race last-node retirement and never needs a fallible shutdown clone. Cancellation waiters reserve their physical record and owners before polling, register before checking signals, and clone/drop/wake executor Wakers outside gates. `Requested` and `Closed` are distinct observations, neither native-job settlement. The companion does not secretly call ordinary allocating context variants. Clock acknowledgment swaps finite batches and destroys ticks outside gates. A pending-ack bit is published before a busy drainer returns; the owning drainer clears/swaps again while requested and restores spare atomically with its final pending check, including single-unwind cleanup. Concurrent native wait or one-shot close acknowledgment is not discarded. Invocation state resets output, failure flags, cancellation, trace and complete frontier before reuse. Loss closes clock intake and acknowledges retained ticks without calling loss asynchronous native success.

`PreparedOutput<A,E>` keeps its record, actual attached node/environment/resource/provider origins and non-Clone result through consumers. See [output-origin storage and transfer](OUTPUT_OWNERS.md) for the pre-work physical attachment, multi-borrow, mapped/future last-consumer, provider final-settlement and native-accounting contracts. Checked shared observers retain the same generation. Last-consumer cleanup takes the result outside its mutex, breaking an output containing a context that retains its own root. Safe mapping borrows the original outcome and returns `LeasedRunResult`, never a bare owned payload. Owned mapping is explicitly unsafe with an actual ownership/settlement contract. A mapped consumer Future acquires a separate transfer owner before any poll; Ready moves that already-owned handle into its output, while the original Future retains ownership until its captured data is destroyed. Future drop is not acknowledgment of detached native jobs; providers must retain actual native job reservations to settlement.

There is one Step/evaluator. Ordinary Context and the prepared companion implement a private readonly drive protocol; publication remains inside the final native hook guard with identical clock/yield/tag handling. Root bookkeeping has no per-run Arc control block or raw-index lifetime assumption. Both prepared-reuse and bounded-allocation backing policies remain distinct. Caller-provided startup environment/recipe dependencies and arbitrary native dependency allocations require their own accounting; pointer size is not coverage.

The root's reserve callback receives its actual admitted target context before the native business body. It can acquire child/bridge/listener owners and return them in the real owned L; L and recipe captures are compiler-counted in Start. `effect_prepare! { reserve_native; context: child }` obtains a complete execution token, and `native_reserved` consumes that token with no later owner copy or capacity attempt. The receipt now reserves the child/token and receipt before its business factory, then formats through this path. The ordinary `effect_prepare! { native; context: child, body: ... }` companion obtains both actual context owners before invoking/polling its lazy factory. Its typed native Future/factory fields drop before both retained context owners (including unpolled and completed destruction), preserving the node/root quota through user destructors and reentrant admission. Its typed native Future and factory captures live inline in the parent Future's compiled layout, not in an uncounted Box or parallel interpreter. `join_prepared_native` waits for both actual native Ready outcomes and retains their Futures/contexts through destruction. It is not a detached spawn or scoped scheduler/provider implementation. Inline native panics currently unwind to the enclosing prepared callback boundary; independent per-child panic recovery still needs the diagnostic ownership work below.

The current checked graph contract is a concrete native Future plus explicit context/listener/clock demand. An opaque existing Effect graph is refused during configuration; refusal is interim safety, not completion of graph adapters. Full generated transitive Effect/workflow/scope/resource graphs, dynamic callback allocation contracts, remaining all-family integration beyond SCHEDULING.md's generated scheduler/provider scoped joins, nonempty trace/instrumentation data, error aggregation, description destruction, dynamic native adapters and all13 integration remain. Output/attachment and borrowed-run ownership for the implemented prepared families now follow OUTPUT_OWNERS.md; this does not certify ordinary erased runs or arbitrary native pointees. **Open accounting defect:** the existing prepared future adapter still calls ordinary `Defect::from_panic`, which allocates a System `Arc<str>` for string payloads. Bounded diagnostic ownership must be reserved before factory/poll and preserve escaped infallibly cloned Defects, CallbackPanic/Die identity, UTF-8 overflow summaries and primary cause. Reclamation/representation policy is pending the user's decision; no irreversible saturation-retention policy or fixed message cap has been selected. Ordinary Defect/Exit APIs and System panic behavior remain unchanged. Preparation-storage callback unwind handling also remains part of that accounting/error integration; currently its ordinary Rust unwind is not a completed prepared Die conversion. No bounded-panic/accounting completion claim applies.

The ordinary Frame-selected scope/resource application and the new prepared-native receipt are real application sources, checked/linted only. No test/fixture/probe/build/runtime/benchmark or native/RSS/performance validation is permitted until the full production milestone, and no whole-process/zero-allocation/512MiB qualification follows from this increment.
