The workspace Cargo wrapper runs the `manual_dsl_construction` compiler lint before the original Rust compiler or Clippy driver. The lint resolves native definitions and receiver types, checks callable references and public representation construction, and accepts only tokens generated by the registered Effect procedural macros. Handwritten expressions interpolated into a macro remain checked. Existing Clippy configuration and arguments are preserved.

Bootstrap the native launcher once from the workspace root using the host target:

```sh
rustup component add rustc-dev --toolchain 1.100.0
cargo +1.100.0 --config 'build.rustc-wrapper=""' build \
  --manifest-path tools/effect-dsl-lints/Cargo.toml --bin effect-dsl-lint \
  --target-dir tools/effect-dsl-lints/target -j2
```

The configuration override applies only to building this launcher. Normal workspace and nested fixture Cargo commands use `.cargo/config.toml` and require the launcher; missing tooling fails the command. No Python or other scripting runtime is required. The launcher compiles the private compiler driver with `RUSTC_BOOTSTRAP` scoped to that driver compilation; production compilation retains its ordinary compiler and lint settings. Rust process spawning preserves Cargo's inherited jobserver descriptors.

`registry.rs` associates every current public macro with its native construction rules, including shared modes, inline/extracted callbacks and facade aliases. Stream-local `yield_from!` and collection-local `item!`/`items_from!` belong to their enclosing macros. Export identity reconciliation and reviewed source fingerprints reject added exports, files or changed lowerings pending rule/fixture review. Fingerprints detect drift; they do not substitute for native rule coverage or pass/fail compiler regressions.

## Cargo outputs and cache maintenance

The launcher path in `.cargo/config.toml` selects the final host binary from the
bootstrap command. The wrapper owns a separate driver directory at
`target/effect-dsl-lints/<key>`. Its key covers compiler version, sysroot and the
driver rule sources. A per-key lock protects driver creation. For a production
compiler invocation, the wrapper uses the supplied `--out-dir` and
`extra-filename` to find that invocation's dependency file and records policy
sources there.

Cargo 1.100 supports separate directories for final output and intermediate
artifacts. Use `build.target-dir`, `CARGO_TARGET_DIR` or `--target-dir` to select
final output. Use `build.build-dir` or `CARGO_BUILD_BUILD_DIR` to select the
intermediate cache. Both are optional workspace/operator settings. A shared
intermediate cache can keep a separate final output directory per worktree.
Cargo's `{workspace-path-hash}` expansion can isolate intermediate storage by
workspace path when separate caches are wanted. [Cargo build cache](https://doc.rust-lang.org/cargo/reference/build-cache.html).

Capture Cargo JSON output from the invocation that produces the artifact. Read
`compiler-artifact` messages using the exact package ID, target kind/name,
profile and feature set. Keep the invocation's target triple with that record.
Use `executable` for binaries or the matching entry in `filenames` for the
required library or proc macro. Report missing or ambiguous selections. Cargo
owns its intermediate-directory layout. The existing compiler fixtures take
their results from the same invocation. Their JSON decoding is tracked in
W13-03 for the validation phase. [Cargo artifact messages](https://doc.rust-lang.org/cargo/reference/external-tools.html#artifact-messages).

For cache retention, distinguish Cargo intermediates, final output, the local
launcher and the wrapper's driver cache. Coordinate cleanup with every worktree
using the selected directories and wait for their Cargo and driver processes to
finish. Retire idle directories through the owning workspace's cleanup policy.
Keep registry caches, installed tools and active outputs outside that cleanup.
Later cache measurements should compare clean and unchanged runs, feature
switches and worktree reuse. Record elapsed time, reused artifacts and final and
peak disk usage for each case.

## Dependency and documentation lints

Workspace manifests inherit the Cargo `unused_dependencies` and
`unused_workspace_dependencies` warnings and the rustdoc
`invalid_markdown_table` warning. `unused_workspace_dependencies` reports
entries that members do not inherit. The package lint depends on the selected
targets, features and dependency scopes. Review default and optional features,
target-specific imports, macros, build scripts and dev dependencies before
removing a dependency. Combine targeted feature graphs with source inspection
for scopes outside the emitted diagnostics. The Markdown table lint applies
when rustdoc runs. [Cargo lint coverage](https://doc.rust-lang.org/cargo/reference/lints.html#unused_dependencies),
[rustdoc table lint](https://doc.rust-lang.org/rustdoc/lints.html#invalid_markdown_table).

## Dependency update and tool install settings

An operator can select a registry cooldown with
`registry.global-min-publish-age` or `CARGO_REGISTRY_GLOBAL_MIN_PUBLISH_AGE`.
Use a duration string in Cargo's integer-and-unit format or `"0"` to allow all
publication ages. `registries.<name>.min-publish-age` overrides the global value
for an individual supporting registry. Under
`resolver.incompatible-publish-age = "deny"`, Cargo excludes versions that
are younger than the configured age unless they are already in the lockfile.
An intentional update may select `allow` for that invocation. Review any
resulting lockfile changes separately from ordinary `--locked` checks.
[Cargo update policy](https://doc.rust-lang.org/cargo/reference/resolver.html#publish-age).

Cargo 1.100's `cargo install` uses the packaged lockfile when available. Cargo
resolves dependencies when the package omits it and warns if `--locked` was
also supplied. A registry install uses user-level Cargo configuration.
`cargo install --path` discovers configuration from the local package path.
The workspace launcher above uses the local pinned bootstrap command.
[Cargo install and lockfiles](https://doc.rust-lang.org/cargo/commands/cargo-install.html#dealing-with-the-lockfile).
