The workspace Cargo wrapper runs the `manual_dsl_construction` compiler lint before the original Rust compiler or Clippy driver. The lint resolves native definitions and receiver types, checks callable references and public representation construction, and accepts only tokens generated by the registered Effect procedural macros. Handwritten expressions interpolated into a macro remain checked. Existing Clippy configuration and arguments are preserved.

Bootstrap the native launcher once:

```sh
rustup component add rustc-dev --toolchain 1.99.0
cargo +1.99.0 --config 'build.rustc-wrapper=""' build --manifest-path tools/effect-dsl-lints/Cargo.toml --bin effect-dsl-lint -j2
```

The configuration override applies only to building this launcher. Normal workspace and nested fixture Cargo commands use `.cargo/config.toml` and require the launcher; missing tooling fails the command. No Python or other scripting runtime is required. The launcher compiles the private compiler driver with `RUSTC_BOOTSTRAP` scoped to that driver compilation; production compilation retains its ordinary compiler and lint settings. Rust process spawning preserves Cargo's inherited jobserver descriptors.

`registry.rs` associates every current public macro with its native construction rules, including shared modes, inline/extracted callbacks and facade aliases. Stream-local `yield_from!` and collection-local `item!`/`items_from!` belong to their enclosing macros. Export identity reconciliation and reviewed source fingerprints reject added exports, files or changed lowerings pending rule/fixture review. Fingerprints detect drift; they do not substitute for native rule coverage or pass/fail compiler regressions.
