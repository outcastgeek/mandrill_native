# AI for Zig

A native AI client library providing provider/model collections, completion and streaming, image generation, classification, authentication, catalogs and client utilities. The application owns tool execution and orchestration.

The compiler is Zig 0.17.0. The standalone regular-expression engine supplies only its standalone regular-expression/Unicode C components, compiled directly by Zig. Package-local `build.zig.zon` also declares the internal canonical `native_build` support used by the native ABI types. The current local dependency path expects this source checkout's `native_build` directory to remain available. No application runtime is installed by importing `ai`.

## Build and consume

From `packages/ai`, `zig build` compiles the native `pi-ai` executable. The `ai` module is exported by `build.zig` with `root.zig` as its root. A consumer build imports `dependency.module("ai")` into its root module. Target and optimization choices are supplied using the ordinary Zig build options. The regular-expression engine is downloaded only as a pinned build input, not at inference time.

`zig build examples` compiles the six programs in `examples/`; it does not run provider requests. `zig build catalog-build` compiles the catalog tool without executing it. The `run` and `catalog` steps execute the CLI and explicit catalog tooling, respectively. These are available package commands, not claims that they have been executed or authorized for the current implementation session.

The current compiler evidence is a successful package-local default build on macOS ARM64 using Zig 0.17.0's LLVM backend. Runtime provider parity, independent consumer execution and other platform support remain unestablished. Tests, runtime probes, parity execution, live provider calls, formatting/lint tools and benchmarks are currently prohibited; the requirements ledger records them as unexecuted.

## Entry points and selective use

`@import("ai")` exposes the native API. `ai.ai` is the core namespace; `ai.providers` is the explicit built-in-provider convenience entry point. Merely importing either namespace performs no registration, credential discovery, network call or catalog update. Calling `builtinModels` explicitly creates the registered built-in collection.

For selective use, call one factory, such as `ai.providers.anthropicProvider(a)`, then set `.providers = &.{provider}` in the options argument passed to `ai.createModels(a, io, options)`. Unused factories remain lazy Zig declarations. The `ai.ai.api` namespace exposes individual wire implementations, and `ai.bedrock_provider` exposes the dedicated Bedrock entry point. Provider/API IDs remain strings so custom IDs are supported. Chat, image and classifier models share the collection, with type-specific lookup and operation methods.

The source provider helper entrypoints are exposed as `providers.model_schema`, `compat_schema`, `radius_config`, `openrouter_api`, `cloudflare_auth`, `cloudflare_stream`, `opencode_headers`, `faux` and `images.register_builtins`. Schema exports such as `ProviderCompatSchema(a)` are allocator-taking builders returning `TSchema`; enum wire trees and native conversion metadata retain their distinct roles. `CompatSchemasByApi(a)` returns an insertion-ordered map, with one shared Responses schema for its three API keys. Release the map storage with `deinit(a)`; the nested schema trees belong to the allocation region. Use an arena for schema construction and release it after all consumers finish. The tools example declares a provider-configuration tool using these public schemas. Open metadata carrier types use the existing native records or `std.json.Value`; validation follows the corresponding schema.

Radius credential/network configuration helpers sanitize model entries. The direct `getRadiusModelsFromConfig` helper instead maps every supplied entry using object spread and overrides only API, provider and base URL. Partial or malformed entry fields survive in the returned Model's JSON metadata; missing required native text slots use empty typed fallbacks with explicit omission marks, and non-text values remain retained until explicitly replaced.

Generated provider `.models` exports are available through `getBuiltinModels`, `getBuiltinImageModels`, `getBuiltinClassifierModels` and their single-model counterparts, selecting the provider ID explicitly. `getAllBuiltinModels` returns all types and `getBuiltinModelDataGeneratedAt` exposes the pinned catalog stamp. `builtinProviders(a)` constructs all 42 factories in source order; it does not install them. Keep its allocation region alive through registrations and requests because factory wrapper callback contexts borrow that region. `builtinModels` keeps those contexts in its collection-owned arena until teardown. Individually constructed providers follow the same factory-region lifetime.

`cloudflareStreams(a, original)`, `cloudflareClassifier(a, original)` and `withOpenCodeSessionHeader(a, original)` allocate wrapper descriptors in `a` and borrow the original opaque callback context. Keep both alive until calls and returned streams have joined. Inner stream implementations copy retained inputs before returning. Cloudflare's stream/classifier helpers retain their source capability selection; OpenCode preserves the original implementation's other capabilities and callback context. The image registration facade takes an explicit `images.Registry` owner, and its generation alias uses the native callback signature with `OperationContext`; imports do not register a global provider.

Classifier APIs are available as `api.typesafe_system_one`, `api.cloudflare_workers_ai_system_one`, `api.openai_decisions` and `api.llama_cpp_classify`. Their direct calls take explicit request auth and preserve API-specific unsupported-model errors. System One maps public bool questions to `noul`; Decisions maps them to predicates, accepts up to 128 images and does not retry HTTP 504. Both retain reported usage if answer decoding fails. Provider dispatch prepares Cloudflare endpoint placeholders before calling its API; direct API calls use the supplied model endpoint.

Cloudflare provider wrappers expand every account/gateway placeholder using the resolved request env before chat, simple-chat, completion or classifier dispatch. Empty replacements, URL delimiters and the pinned string replacement's dollar substitutions are retained; each wire API performs subsequent URI construction. Account expansion precedes gateway expansion. A key-only stored Cloudflare credential can obtain account/gateway fields from the environment, while an explicitly stored empty field remains empty. Gateway auth supplies `cf-aig-authorization` and provider-auth tombstones; Workers AI supplies its API key. Direct API calls use the supplied model endpoint and env without applying the provider wrapper.

OpenCode Go and Zen add `x-opencode-session` before chat dispatch when a nonempty session ID is supplied and the request headers contain no case-insensitive spelling of that name. An explicitly supplied null also prevents automatic insertion. This applies to normal/simple streaming and completion; Zen's System One classifier uses its own API without the chat session wrapper. Factory model catalogs retain each model's protocol endpoint and compatibility metadata.

System One and Decisions construct the pinned trimmed-base string plus slash, then resolve their endpoint name through `std.Uri.resolveInPlace`. Existing base queries/fragments are discarded by that relative resolution. Broader WHATWG URL differences remain tracked in the ledger.

The llama.cpp classifier validates every question before requests, repeats the JSON state around the question overview, resolves single-token labels, and reads increasingly deep next-token probability lists before applying temperature and confidence calculations. Label lookups and ordered null/duplicate checks form one concurrent branch against prompt rendering, preserving which branch fails first. Label lookup storage belongs to the transport; custom transports can provide `labelTokenCache` to share lookups between requests. Native concurrent groups join their work before freeing request storage. The server-root helper retains the pinned whole-string suffix rules, including query/fragment cases.

`ai.compat.Registry` owns the older registry-style API and image registry. Its registration, replacement, source-scoped unregister and reset operations are explicit; there is no process-global registration side effect. `ai.oauth` exports the nine native OAuth flows and extension-compatible callback types. Native factories statically reference the flows they use, replacing the standalone application's dynamic/static JavaScript loader distinction.

An embedding UI can use `auth.PromptOwner` when manual prompts may finish after a browser callback. Create the owner outside login with an allocator and Io backend that remain alive through UI shutdown. Its required context retain/release callbacks own the UI context. Pass `owner.interaction(errorMessage)` to login. Each prompt receives an independently owned JSON value, result allocator and cancellation event; callback success or login cancellation joins only the cancelable waiter. A late producer retains its storage and context until completion, then releases abandoned storage automatically. Stop login calls before `owner.deinit()`, which cancels and joins the owner's remaining producers before releasing the UI context. Existing synchronous `Interaction.prompt` callers remain supported. The auth example exposes creation and login helpers for this boundary.

Chat compatibility registration preserves insertion order and captures a distinct wrapper identity on every replacement. Registering chat built-ins preserves existing overrides; reset reinstalls the defaults. Image compatibility registration dispatches by API with explicit request auth; collection image operations resolve provider auth. Registering image built-ins replaces the OpenRouter entry as in the pinned implementation. Static image getters return only image models and report unknown providers/models with an empty slice or null.

`ai.bun_oauth` names the same statically included native OAuth namespace. The compatibility OAuth entrypoint installs loaders for these nine flows; native provider factories already reference them directly, including the configured Radius flow. Native consumers use those declarations directly without a loader-registration step.

`api.azure_openai_config` exposes typed `AzureEndpointOptions`, deployment-name, base-URL and combined-config helpers. It takes explicit allocator, `std.Io` and optional `AuthContext` arguments for ambient fallback; explicit fields keep the source lookup order. Base-URL normalization shares the Azure adapter, whose remaining WHATWG URL cases remain tracked in the ledger. `api.cloudflare` exports the five endpoint templates.

`api.classifier_shared` exposes finite-number/record/usage helpers and `postClassifierRequest`, with optional owned HTTP/timeout detail alongside its error union. Callback and cancellation failures retain their own diagnostics without a prior response's status/body. `api.system_one_shared` exposes `SystemOneWireRequest`, an injected `SystemOneTransport` and `classifySystemOne`; transport callbacks supply URL, payload envelope and output extraction, while the shared implementation converts bool questions, parses usage before answers, validates answers and returns the classifier result. Callback error-message slots retain native exception details.

`api.openai_completions.ConvertCompletionsMessagesOptions` and `convertMessagesWithOptions` accept an explicit read-only grammar-property map; the existing conversion convenience path derives it from declared tools. `api.openai_responses_shared` exposes conversion options, caller-selected allowed providers, grammar/tool options and decoded-event processing. `ResponsesEventIterator` replaces the source async iterable and borrows its context through return. `processResponsesStream` updates the supplied output and emits content events; the outer caller owns start/terminal publication and framing. Its result allocations use the supplied region, including partial results on failure. Service-tier resolution/pricing callbacks see the current output and mutate its usage; callback errors propagate. Retain map and callback contexts for the call. `simple_options.buildBaseOptionsWithApiKey` supplies the source helper's explicit-key argument, and `google_shared.retryGoogleRequest` uses the native provider-error interface for status/header normalization.

`api.bedrock_converse_stream.BedrockProviderModule` owns the source module-override state. Set it with `setBedrockProviderModule(owner, io, implementation)` and create an owned lazy adapter with `bedrockConverseStreamApiWithModule`; each dispatch consults that owner. Retain the owner, lazy adapter and every selected or replaced implementation until its streams have joined. The ordinary factory remains available for direct native inclusion.

`utils` exposes the utility modules, including direct-import helpers from the source package. Native `utils.abort.operationSignal` selects an optional supplied `std.Io` or an explicit fallback. `ObservedOperation(T)` owns a concurrently produced result and its arena; `raceWithAbortSignal(T, &operation, io)` stops waiting on caller cancellation while the owner continues observing the operation. Retain producer contexts through `deinit`, clone results that must outlive the operation, and give teardown to one owner after waiters stop using its state. `utils.abort_signals.AbortSignal` owns a standard event and a copied diagnostic reason. `combineAbortSignals` returns no signal for zero inputs, reuses a single input, or owns synchronous registrations and a new signal for multiple inputs. The first abort reason wins and is published before the originating `abort` call returns. Combined reasons are copied, so they survive registration cleanup. `cleanup` detaches registrations and waits for active publication; `deinit` releases the combined signal. Inputs remain valid through cleanup, and dependent combined signals are detached before their inputs are deinitialized. Task cancellation uses native `error.Canceled`; explicit notifications retain native errors, exception details or thrown JSON/text values. A reason-copy failure publishes its native error as the signal reason. The auth example demonstrates these explicit lifetimes. `utils.oauth_page` supplies allocator-owned success/error HTML using the pinned template and standard string replacement for HTML escaping. `utils.uuid.uuidv7` takes an explicit `Generator` owner, as does the root alias.

`examples/compatibility.zig` shows registry construction, scripted provider registration, completion and disposal. Compatibility functions such as `ai.compat.complete(&registry, ...)` also remain registry methods. Its direct API aliases take `OperationContext` and a normalized `TranscriptContext`. `ai.compat` re-exports the core names, legacy stream aliases, image catalog and registry functions, built-in provider type, callback types and environment-name constants. The legacy `ANTHROPIC_IDENTITY_TOKEN_FILE_ENV` constant remains an exported name; credential-file retrieval is prohibited and is not enabled by that constant.

`ai.models` exposes provider/collection construction, registration, lookup, dispatch and model helpers, including `ModelsError` and `ModelsErrorCode`. Custom provider/API IDs stay open strings. Supply one `.streams` implementation for all chat APIs, or API-keyed `.apis` records with chat, deferred, image and classifier callbacks as needed. Factory inputs borrow their caller; registration clones retained values and uses optional context clone/destructor callbacks for host-owned state.

Collection registration replaces a provider in its existing insertion position; deleting and re-adding it moves it to the end. Lookup uses last-known snapshots and does not refresh catalogs. Ordinary model-list callback failures yield no models in best-effort getters; native cancellation and allocation errors propagate. Availability checks run concurrently, retain provider order in their results and apply credential-specific filters after auth configuration checks. Model-list callbacks run outside the collection mutex so they can reenter collection lookups.

Transcript replay helpers preserve the source message list. Section and tool replacement keep insertion order; removals followed by additions move entries to the end. Collapsing system messages creates a new leading system message and message list. An operation arena owns the returned composite structures, while unchanged messages/tools can still borrow input slices. `contentText` borrows string input and allocates joined block input; complete system-text rendering allocates its returned text. `toToolDeclaration` clones wire fields and drops native schema-construction metadata, matching the reference JSON round trip.

`transformMessages` first normalizes null or missing content to an empty list. It keeps same-model signed/redacted reasoning, removes foreign thinking, rebuilds foreign text with only its type/text fields, and removes a foreign tool call's truthy thought signature before optional ID normalization. Tool-result IDs follow those mappings. Non-vision image placeholders collapse consecutive image runs; error-result image splitting retains the images and caption separately. Orphaned calls receive synthetic error results before held system updates are released. Errored/aborted assistant turns are omitted after the ordered normalizer pass. Message records retain tool details, nested call records, optional tool usage, response IDs and actual response model as data; the library does not execute those calls.

## Minimal completion

This is the shape used by `examples/completion.zig`. It assumes a provider/model ID selected by the application and credentials available through the explicit context or supported acquisition path.

```zig
const std = @import("std");
const ai = @import("ai");

pub fn main(init: std.process.Init) !void {
    const io = init.io;
    var request_arena = std.heap.ArenaAllocator.init(init.gpa);
    defer request_arena.deinit();
    const a = request_arena.allocator();
    const args = try init.minimal.args.toSlice(a);
    if (args.len != 4) return error.ExpectedProviderModelPrompt;

    var environment = ai.EnvironmentContext{
        .allocator = init.gpa,
        .environ = init.environ_map,
    };
    var models = try ai.providers.builtinModels(init.gpa, io, .{
        .authContext = environment.context(),
    });
    defer models.deinit();
    const model = (try models.getModel(args[1], args[2])) orelse
        return error.UnknownModel;
    var result = try models.complete(a, model, .{
        .messages = &.{.{ .user = .{
            .content = .{ .string = args[3] },
            .timestamp = std.Io.Clock.real.now(io).toMilliseconds(),
        } }},
    }, .{}, .{});
    defer result.deinit();
    _ = result.value(); // Read or serialize the owned assistant message here.
}
```

`completeSimple` and `streamSimple` apply the pinned simple-option mapping before dispatch. `complete` returns `Owned(AssistantMessage)`. `generateImages` and `classify` use their corresponding context/options/result types. Deferred operations use `streamDeferred`, `fetchDeferred` and `cancelDeferred`. `examples/tools.zig`, `custom_provider.zig` and `auth.zig` show tools as returned data, an application-owned provider and custom authentication. `examples/consumer` is a separate application build whose manifest declares only `ai`; its build imports only `dependency.module("ai")`. It can be compiled from that directory with `zig build` without executing its example.

## Ownership and concurrency

| Boundary | Contract |
|---|---|
| Allocator and `std.Io` | Supplied by the application. Keep both alive through all requests and teardown. Use an allocator suitable for concurrent allocation when streaming or using a concurrent HTTP backend. The package does not create a private I/O backend per request. |
| `Models` | Owns registered snapshots, its default memory stores, default HTTP client, auth state and session resources. Finish/join active calls and destroy their stream handles before `Models.deinit()`. Externally supplied stores/transports and their callback contexts stay application-owned. |
| Provider registration | Clones retained value data. Opaque callback contexts remain borrowed unless the provider supplies the corresponding context-retain/clone ownership hooks. Keep borrowed contexts alive while registered and while existing requests use them. |
| Lookup results | Model/provider values contain borrowed slices from collection snapshots. Keep `Models` alive. Enumeration functions allocate the outer result with the supplied allocator; dynamic results can also allocate nested data there. An operation arena is convenient. Use `ai.Owned(T).clone(a, value)` for an independent retained value. |
| `Owned(T)` | `value()` borrows the wrapper's owned tree. `deinit()` releases it. A second clone is independent. |
| Stream handle | Returned by `stream`/`streamSimple`; allocated with the supplied allocator. `destroy()` cancels and joins its producer, then frees the handle and its retained data. `deinit()` alone is for a caller-owned handle value. |
| Events and final result | `next()` and `result()` return values borrowing the handle until destruction. Publication deep-clones event data, so later network/reducer buffers do not overwrite previous events. Repeated `result()` reads borrow the same retained result. Clone to keep data beyond handle destruction. |
| Producer lifecycle | One owner calls `cancel`, `awaitProducer`, `deinit` or `destroy`; do not concurrently await/cancel the same future. Independent `next`/`result` waiters use the handle's synchronization. A caller can request only `result()` without draining events. Streaming requires `io.concurrent`; lack of backend concurrency is an explicit error. Direct completion drives the reducer synchronously. |
| Request inputs | Stream construction clones retained model/transcript/value data. Function pointers, telemetry context, callback contexts, injected transports and opaque pointers remain borrowed; retain them through producer join. Callback-visible working values borrow the active request unless cloned. |
| Callback output | Allocate retained replacement JSON through the callback's allocator. Payload replacement/mutation uses decoded `std.json.Value` trees. `onResponse`/provider-event callback arguments borrow the request; clone before retaining. |

Streaming response observers run before consuming provider events. Bedrock's raw observer also sees unsuccessful HTTP responses before error-body handling; callback failures leave the request without a transport retry. Google adapters expose parsed provider chunks without an HTTP response observer, matching their pinned SDK surface. Image and classifier helpers invoke `onResponse` after their request/response-decode retry completes. A payload callback's optional `null` keeps the working tree; return a present `JsonValue.null` to replace it with JSON null. Treat parsed provider-event trees as read-only.

OpenRouter images use the pinned chat-completions image payload, retain returned text and data-URI images, and skip remote image URLs. Usage and already-decoded output survive a later image decoding failure. The SDK response branch uses Content-Type to select JSON or text, distinguishes an empty JSON body from JSON null, and observes a payload-selected streaming response before reporting its missing image-result fields. Successful buffered responses share the request's remaining timeout budget; stream, 204 and explicit zero-length responses use the pinned bypasses. Body timeouts can enter the outer provider retry policy. Returned image results own their retained data.

Pi Messages posts the model, transcript and selected options to the trailing-slash-trimmed whole base URL plus `/messages`. Debug updates the `debug` query entry while retaining other entries. The response observer runs before HTTP status handling, and the provider-event observer runs before conversion. Explicit start/block/end events are forwarded, including repeated events, extra event fields and indexed block replacement; deltas mutate the property selected by the incoming event kind. Falsy decoded frames are skipped before observation, while truthy unknown events retain their tree. A terminal event stops consumption without synthesizing block ends. Tool-call end values merge into the current block; its event uses the `Content` carrier to retain the resulting object. Non-index numeric properties of the content array remain available in `jsonContentProperties` and are omitted by JSON array serialization. An abrupt failure creates a fresh empty assistant result; cancellation omits HTTP failure diagnostics. This adapter supplies no request timeout or retry policy. Radius catalogs replace the shipped baseline once a stored or refreshed account catalog exists; custom providers may select the same direct API. Deferred handles remain ordinary serializable message metadata.

OpenAI client headers are captured before the payload callback. Ambient `OPENAI_CUSTOM_HEADERS` lines first form a case-sensitive ordered object, then pass through case-insensitive normalization. Image model/options headers likewise undergo the pinned object spread before `providerHeadersToRecord`; OpenAI chat defaults retain their own ordered object stage. Caller defaults override ambient custom headers, and JSON body headers are applied afterward. The default ten-minute request timeout does not itself emit `X-Stainless-Timeout`; that header reflects an explicit nonzero request timeout. These environment values enter through the supplied auth context.

Anthropic generates session-affinity headers only for API-key, header-owned and federation clients. OAuth and Copilot clients retain supplied model/request affinity headers without synthesizing one. `ANTHROPIC_CUSTOM_HEADERS` enters through the supplied auth context before the payload callback and shares one ordered object stage with caller defaults before SDK normalization. The SDK's `x-stainless-helper` header accumulates unique comma-separated tokens, and an explicit null clears it. Payload beta/profile/workspace fields become their request headers; an empty beta array supplies an empty header that overrides a previous value.

Codex SSE uses the pinned implementation's uncompressed JSON fallback. The library does not add a request `content-encoding: zstd` header. WebSocket requests likewise send JSON text frames. This path requires no request compressor or additional dependency.

`uri.encode` retains ordered RFC 3986 query fields for AWS Query/signing. `uri.encodeForm` supplies the separate OAuth/Google `URLSearchParams` representation: repeated fields stay ordered, spaces become `+`, literal plus signs are percent encoded, and the form safe-character set applies. Standard URI encoding/decoding and Unicode formatters handle escapes and scalar-string conversion. Callback query lookup decodes `+` as space and returns the first repeated key. HTTP URL hosts use the approved Unicode 17 IDNA/Punycode adapter and typed WHATWG IPv4/IPv6 normalization; std.Uri retains component parsing, percent codecs and path resolution. Broader URL/schema behavior remains tracked separately.

Token estimates count UTF-16 units and use the latest applicable successful assistant usage plus subsequent message estimates. Cost tiers select the highest threshold strictly below the request's input plus cache reads/writes. One-hour cache writes are a subset of cache writes, charged at twice the selected input rate. Bedrock leaves that optional split absent when cache details are absent. Responses service-tier multipliers follow the adapter and model; a tier with multiplier one preserves the supplied cost record. Durations use the monotonic clock; message timestamps and credential expiry use wall time.

`calculateCost(a, model, &usage)` returns an error union containing the updated cost record. Ordinary numeric inputs require no allocation; retained JSON inputs use temporary storage from `a` for source numeric conversion, string addition and UTF-16 relational comparison. A selected raw threshold remains raw for subsequent comparisons. Cost fields are assigned in source order, so a later conversion failure preserves earlier assignments. OpenRouter pricing uses the source `parseFloat` prefix conversion and six-decimal rounding. Provider usage reducers retain raw field assignments, their distinct truthy/nullish defaults, and the source's computed or reported totals. Responses, Google, Mistral and Bedrock leave accumulated usage unchanged when the incoming usage record is falsy; Anthropic recalculates totals and costs after every message delta. OpenRouter images retain their separate direct rate calculation without chat tier selection or the one-hour write adjustment.

`utils.estimate.calculateContextTokens(a, usage)` returns the selected standard JSON value, preserving a truthy reported total or the source's left-associated addition. `estimateContextTokens` retains nonnumeric totals in its result's JSON metadata; its native numeric slots remain available for ordinary inputs. Context-window clamping reads the retained total and applies numeric conversion at the subtraction, as the source does.

Assistant messages retain all seven stop reasons, provider raw stop/end-turn fields, optional reasoning/cache splits, diagnostics and deferred handles. Diagnostic trees retain their type, timestamp, error name/message/stack/code and detail fields through ordinary cloning and JSON serialization. Final stream messages receive a rounded nonnegative duration only when no duration is already supplied and their timestamp does not predate the stream; forwarded older/deferred results keep an absent duration. Deferred handles keep opaque provider conversion data alongside their provider/model/API/ID and optional expiry/poll delay.

Public message timestamps, durations, deferred expiry/poll delays, catalog timestamps, OAuth expiry, token budgets and request/retry numbers use binary64 values. Internal typed-to-tree conversion and `json.from` preserve non-finite numbers for payload observers; `json.stringify` and direct record serializer hooks convert them to JSON null only when encoding. `json.roundTrip` is reserved for source operations that explicitly serialize and parse, including transcript tool parameter declarations. Tool comparison first constructs those declarations, preserving their source field selection and property order.

Public tagged values keep the source wire discriminators: messages use `role`; content, assistant events, classifier questions/answers, constrained-sampling values and stored credentials use `type`. Their native unions keep the source tag spelling, including `toolCall`, `toolResult`, `api_key` and `oauth`. Model/API/provider IDs remain open strings; known-ID enums are conveniences. Model, image and classifier aliases share a native carrier, as do several request-option and stop-reason aliases; each operation selects the applicable fields and model kind. ## Authentication

`EnvironmentContext` borrows the application's environment snapshot. `AuthContext.inputs` carries borrowed in-memory credential documents, tokens and authentication certificates. Retain these immutable inputs for the context/request lifetime. They are unresolved inputs: the library still performs supported metadata HTTP, credential-helper invocation, OAuth exchange/refresh, STS acquisition and local signing.

Compatibility environment-key discovery checks Vertex ADC path existence through `AuthContext.fileExistsFn`; it never reads credentials. `EnvironmentContext` owns the sticky ambient discovery cache. Custom contexts can supply `vertexAdcExistsCache` with initial value zero for the same behavior, or omit it for fresh discovery each call. A nonempty provider-overlay `GOOGLE_APPLICATION_CREDENTIALS` path bypasses the cache. The authenticated marker also requires a project and location; compatibility dispatch does not inject that marker as an API key. Bedrock web-identity path presence reports availability without retrieving its token file.

Provider auth resolution checks an explicit API-key override before reading the credential store, including empty and explicitly marked null values. Stored credentials remain authoritative; missing handlers and OAuth failures do not fall through to ambient keys. Request env values merge into the stored credential's decoded env object without dropping null entries. Cloudflare's per-field fallback distinguishes absence from null or empty values. Vertex's provider resolver checks the selected ADC path, or its default path, before accepting project/location; supplied native credential documents and stored login JSON remain supported. Bedrock web-identity and Anthropic federation token-file environment markers report availability without reading their files. Specialized environment reads and Vertex discovery check cancellation around the supplied callbacks.

The package must not retrieve credentials from the filesystem, including through a host callback directed to read a credential file. AWS shared profiles, web-identity/container authorization tokens, SSO/login cache documents, Google ADC/subject tokens/executable output caches, authentication certificates/private keys, Anthropic identity tokens and CLI records are not loaded from disk. Ordinary noncredential configuration, machine information and trust-store reads are separate operations. Persistence writes are not categorically prohibited.

`auth.CredentialInputs` fields provide:

- `awsConfig` and `awsCredentials`: profile-name-to-property objects; `awsSsoSessions` and `awsServices`: corresponding section objects. Resolution retains profile and setting precedence.
- `awsSsoTokens` and `awsLoginTokens`: documents keyed by session ID (legacy SSO uses its start URL). Refreshed documents are retained in client-owned memory.
- `awsWebIdentityToken` and `awsContainerAuthorizationToken`: raw token text for the existing acquisition paths. Environment keys, metadata endpoints, credential helpers and bearer credentials remain available.
- `googleCredentials`: decoded service-account, authorized-user, external-account or impersonation input; `googleSubjectToken`: the token replacing a file-based external subject source. Executable helpers still run when explicitly enabled, and their stdout is decoded with `std.json`; persisted executable caches are not read.
- `googleCertificate`, `googleCertificateChain` and `googleCertificatePrivateKey`: supplied authentication material used for certificate subject tokens and client identity. Certificate configuration path fields are not followed to retrieve authentication material.
- `anthropicIdentityToken`: the assertion used by the federation exchange. The environment alternative is `ANTHROPIC_IDENTITY_TOKEN`, alongside the existing federation-rule/organization settings.

Vertex service-account login prompts for credential JSON rather than a credential-file path. Its `GOOGLE_CREDENTIALS_JSON` scoped environment value is parsed with `std.json`. API-key precedence and metadata acquisition remain separate paths.

The default credential store is in memory. Custom `CredentialStore` implementations provide `read`, metadata-only `list`, transactional `modify` and `delete`. Read/mutation results are cloned onto the caller's allocator. Mutation callbacks borrow a transaction snapshot until they return; the store clones committed data. Credential refresh executes within the provider transaction; a failed refresh retains the prior credential. Store callbacks must honor the filesystem credential-retrieval prohibition.

`Models` owns auth-resolution jobs independently of each request allocator. Cancellation returns promptly while a queued refresh is canceled; an active refresh and its transaction finish under the 15-second refresh deadline, preserving rotated credentials. Post-refresh auth derivation remains observed by the owned job. Each job copies input values and keeps its diagnostics private, then copies a successful result into the caller's allocator. Collection teardown joins these jobs before releasing provider contexts, stores or transport. Custom stores must honor `Mutation.completeOnCancel`: cancel lock acquisition, then shield the callback and commit after acquisition. Standalone `auth_resolution.resolveProviderAuth` takes an `AuthResolutionOwner`; retain borrowed callback contexts through its `deinit`, stop callers before teardown, and use an allocator supporting concurrent access. Completed jobs are reaped on resolution entry/exit or explicit `reap()`; abandoned jobs retain their private allocations until a subsequent reap or teardown.

Default-store mutations and deletes serialize per provider, including after deletion and re-addition. Returning null from a mutation leaves its record unchanged; throwing also preserves it. List exposes only provider/type metadata in committed insertion order. Replacement prepares the caller result and retained credential before committing either metadata or token state.

`ModelsStore` is a separate application-owned catalog interface with `read`, `write` and `delete`; Models supplies an in-memory default. Entries include models of every type, wall-time `lastModified`/`checkedAt`, and an opaque `etag` retained with its quotes. The default clones writes before retaining them and clones reads into the caller's allocation region. Keep custom store contexts alive through all refreshes and collection teardown.

`Models.refresh` first gives each selected dynamic provider a cache-only phase, including when credential reads fail. It resolves credentials only for the subsequent network phase, rereads the catalog store for that phase, and passes `force` as an optional bool: omitted during cache-only work, then exactly the caller value. Unknown model types are filtered from stored and fetched lists; the default fetch wrapper overlays its baseline by model type and ID. Radius instead replaces its baseline once an account catalog exists, including an empty one, and imports a legacy OAuth catalog only when no model-store entry exists. Constructors and ordinary lookups do not fetch or restore a store implicitly. Freshness decisions and use of stored ETag/Last-Modified validators belong to provider callbacks; the pinned built-ins do not add a conditional catalog request policy.

Catalog refresh jobs own private arenas and diagnostics independently of the refresh caller. Cancellation or superseding stops waiting promptly; the collection observes outstanding work and joins it before releasing provider contexts, stores or transport. A started OAuth rotation still commits. Late catalog publication is rejected by cancellation/generation checks, provider failures are reported in completion order, and returned errors are copied before abandoned job storage can be reclaimed. Keep the collection, concurrent allocator and borrowed callback contexts alive through teardown. Completed abandoned jobs are reclaimed on a later refresh or collection teardown. `ModelsPublication.models` is an optional native snapshot extension; omit it for persistence-only or provider-owned update callbacks.

Model publication checks the provider generation before persistence and again when committing its owned catalog snapshot. It prepares that snapshot and a detached persistence input before the store mutation; a persistence failure leaves the previous catalog and provider-private state intact. Publications for one provider remain serialized. Its synchronous `update` callback runs after that commit with the collection mutex released, so it can look up collection models. Replaced contexts and old catalog snapshots remain retained until collection teardown; an already committed publication returns success even if its callback replaces the provider.

Codex access-token claim decoding extracts the account ID for request routing. It does not verify the token signature, issuer, audience, expiration or account identity. Provider reasoning/text/thought signatures and encrypted reasoning data are opaque values: same-model replay retains their bytes, subject to the adapter's wire-shape checks; foreign-model handoff follows the transcript transform's signature-removal rules. Parsing a JSON envelope or checking a signature's Base64 shape does not authenticate it.

`StreamOptions.telemetryContext` is an opaque caller-owned pointer. Models, compatibility dispatch, typed API options, simple-option conversion and deferred/lazy requests forward the same pointer to the provider implementation. Keep its target alive until completion and producer join. The package does not install a telemetry runtime or exporter.

Anthropic token exchange and refresh retain returned token fields without requiring nonempty strings or a positive lifetime. Expiry uses the source numeric conversion and five-minute subtraction, including zero, negative and non-finite results; JSON serialization alone converts non-finite numbers to null. Missing/non-string tokens remain represented in credential JSON metadata, and refresh requests use those retained values. Typed downstream authentication of malformed token values remains unfinished. Browser callback success/failure pages now use the pinned HTML templates through the shared page utility, with HTTP status and cache headers retained. These source changes compile in the shared example graph; the original OAuth ledger items remain open and runtime parity is unverified.

OAuth interaction is an injected `auth.Interaction` with prompts, notifications and an optional diagnostic slot. The host presents URLs/device codes; the library does not launch a browser. The native CLI provides `help`, `list` and OAuth `login`. A successful new-file login writes `auth.json`. If that file already exists, login preserves it and returns an explicit error because merging would require the prohibited credential read. This is an intentional native adaptation of the reference read/merge/write behavior; existing-file merge parity is not claimed.

## HTTP and Cloudflare hosts

`ai.transport.Transport` is a context pointer plus callbacks. A host receives the method/custom method, typed URI including query, headers, raw byte body or `RequestBodyStream`, and returns a `Response` with a reader and one release callback. `bodyPresent=false` represents an absent Fetch body, which Pi distinguishes from a present empty reader; it defaults to true for existing hosts. The default transport marks HEAD and null-body status responses absent. The caller releases each response exactly once using `deinit()` or `abort()`. The reader/header storage and its owner remain valid until release. Timeout paths cancel/join work before releasing borrowed inputs.

Native SigV4 signs the serialized request body that transport sends. Each retry signs again after retry headers and clock correction are applied. The Smithy profile retains repeated/bare/empty query grouping, inherited-property behavior (including the `__proto__` array-prototype effect), strict decoded percent/UTF-8 validation, signature-query omission, path normalization and canonical header exclusions/order. Google federation uses its separate raw path/query profile without checksum injection; its header case variants are combined before canonicalization. Standard URI codecs perform escaping, and standard SHA-256/HMAC primitives produce the signature. `signing.Output` owns returned header/signature bytes until `deinit`; callers copy them before releasing it. No credential values are interpolated into signing errors.

The default HTTP backend uses `std.http.Client` and the application's `std.Io` for inference and token/metadata exchanges. Ordinary TLS uses `std.crypto.tls.Client`. Supplied client identities use an attributed Zig 0.17 TLS compatibility implementation for certificate negotiation while retaining standard HTTP connection/request/response codecs and standard cryptographic primitives. Signing returns headers/signatures to those request paths; auth stores and retry policies remain in their owning layers. Injected transports and credential helpers retain their explicit host interfaces.

The AWS event-stream decoder reads each advertised frame length, checks its prelude and message CRC32, and exposes typed headers and an opaque payload. Integer and timestamp headers use signed native integers; UUID headers use their 16 bytes. Header lookup selects the last duplicate. Returned values borrow the decoder until its next call or teardown; the Bedrock adapter parses JSON payloads into its request-owned region before advancing. A partial prelude, header or payload is an error.

Mistral validates the header-only timeout before wire serialization and leaves response-body reads outside that deadline. Header construction validates names and ByteString range, normalizes HTTP whitespace, applies model then request overrides (including null deletion), and adds affinity only when no explicit affinity key exists. Streaming tool snapshots retain `partialArgs` until finalization or failure; current request/schema/parser diagnostics survive an earlier error finish reason. Endpoint construction uses standard URI resolution with a normalized directory path, lowercase scheme/host and omitted default ports. The shared transport now emits checked WebIDL eight-bit header units through standard Unicode conversion and typed I/O, and widens received units before standard Unicode formatting. Full WHATWG host/path normalization remains unfinished in the Mistral item. Its current source compiles in the shared example graph; runtime parity is unverified.

SSE framing uses adapter-specific rules. OpenAI uses its SDK's line behavior. Anthropic flushes a pending record at EOF, strips only the initial BOM and parses event JSON through the approved repair helper. Its line parser observes explicit logical body-read chunks: a CR consumes an LF only when both occur in the same chunk; a leading LF on the next chunk can dispatch the pending event. An absent Anthropic body produces the source diagnostic after the start event. Codex uses LF/LF records, Pi normalizes CRLF before splitting LF/LF and takes the first data line, and Mistral trims the start of each colon-marked data line. Google uses its restricted record delimiters and treats the whole record after `data:` as one payload. Its EOF suffix check delegates UTF-8 validity to standard codecs and leaves pending bytes unflushed. Google SDK chunk-level JSON error detection remains tracked separately.

`Response.nextChunkFn` lets a host supply each original logical body-read chunk, borrowing its bytes through the next call or response release. Null means EOF; an empty chunk does not. The supplied buffer is optional scratch storage for the host. Anthropic framing consumes `nextBodyChunk` so these boundaries survive buffering in the SSE decoder. A byte-reader-only transport, including the standard backend, uses an explicit native read policy: consume already buffered bytes, otherwise perform a standard `readVec`, with an 8192-byte destination. That policy defines native logical chunks and does not claim browser Fetch segmentation or equate Reader refills with original Fetch reads. `body` and the chunk callback are alternate views for one consumer; a host that needs particular boundary-sensitive behavior supplies its chunk callback.

`Request.bodyStream` is a single-use reader with optional content length and an optional underlying read-error callback. It is mutually exclusive with the existing byte `body`. Keep its owner alive through send and response release. Injected transports receive the same reader without eager buffering. The default HTTP backend streams standard content-length or chunked framing and cannot replay a consumed stream on redirects; a 303 can discard the body and switch to GET. It rejects GET/HEAD bodies as Fetch does.

`ai.createAiBindingFetch(AiBinding)` captures the binding's `fetchFn` at construction and returns a transport. No URL, method, query, header or body transformation is performed by the adapter. The host implements the actual binding call. `CLOUDFLARE_GATEWAY_BINDING_AUTH_SENTINEL` has the pinned value `cloudflare-gateway-binding`; binding-routed callers can use it in `cf-aig-authorization` and explicitly omit provider authorization headers as in the reference binding contract.

JavaScript/Bun/browser host facilities are represented by explicit native contexts, callbacks, `std.Io`, the loopback callback server and the binding transport. The package does not embed a JavaScript runtime.

## Catalogs, schemas and current limits

`data/` contains the frozen model-data snapshot and integrity manifest; Builds use it offline; catalog import/update is an explicit developer operation. `Models.refresh` accepts network/cache/force/provider selection and reports per-provider errors. Provider, model type and model ID form the catalog identity; use type-specific lookups when IDs overlap.

Catalog models retain costs and pricing tiers, modalities, input limits, prompt-cache lifetimes, thinking maps, sampling defaults and compatibility trees. `Model.extra` preserves unmodeled top-level wire properties such as Radius `enabled`, `lab` and `providers`; serialization writes them back as ordinary properties, with declared model fields taking precedence. Like the other decoded JSON metadata, these trees borrow the parsing region until cloned with the model.

The explicit catalog tool supports `check <data-dir>`, `list <provider>` and `import <provider> <input.json> <output-dir> <generated-at>`. Import uses the supplied RFC 3339 generation timestamp, preserves the input shard bytes, and writes a deterministically sorted integrity manifest with standard JSON/SHA-256. The output directory must already exist and contain the other provider shards. Check validates the exact provider JSON file set, required fields in the original JSON trees and manifest hashes, reporting the first native validation error. It accepts open metadata and finite cost rates according to the pinned catalog checker. Builds do not scrape model sources or fetch a latest catalog.

`Type.Typed(NativeType, schema)` binds a runtime schema to an explicit Zig type, and `Static(@TypeOf(binding))` returns that type. The wrapper serializes only the original schema tree. `Static(comptime_schema)` also derives native scalar/array/tuple/object/union types from compile-time construction metadata; generated native unions use `variant_N` tags. Option-taking `UnionWithOptions`, `LiteralWithOptions` and `NullWithOptions` retain the original native constructors' arities.

Constrained sampling derives provider schemas from a cloned tool schema. Strict conversion rejects the pinned unsupported constructs, recursively closes objects, requires each declared property and wraps optional non-nullable properties in a nullable union. `prefer` falls back only for unsupported strict schemas; `require` reports the tool-specific failure. Provider keyword predicates return `anyerror!bool`, so callback errors propagate. Grammar selection prefers a nonblank Lark definition, otherwise regex, and requires one declared required string property. Missing/null variant containers and malformed parameter schemas retain their distinct diagnostics. Completions applies strict support unless its compatibility flag is exactly false; Anthropic applies its provider keyword rules and nullish legacy schema defaults. Local argument validation uses the original schema independently of provider constrained-sampling support. Broader local validation/reference/format work remains in its own ledger items.

`constrained_sampling.appendGrammarToolInputJsonDelta` and its diagnostic-slot variant take an allocator and caller-owned `GrammarToolInputJsonBuffer`. Keep the buffer input and returned fragments alive in that allocation region. The helper requires an append-only input, emits no delta for an unchanged open value, closes an empty value when requested, and makes repeated identical closes a no-op. Changed closed/non-monotone values return the pinned property-specific diagnostics. Standard JSON writes property names and string escapes; only the approved opening/closing string delimiters use explicit framing. Completions closes custom calls at block finalization; Responses also closes on input/item completion. Both publish grammar deltas before their tool end events and keep parsed argument objects in snapshots. Lone-surrogate string compatibility remains the separate unfinished JSON item.

Native WebSockets validate the HTTP upgrade and SHA1/Base64 accept key, own their handshake headers, and negotiate neither extensions nor subprotocols. The frame codec checks masking direction, reserved bits/opcodes, canonical lengths, control frames, close codes and UTF8; it reassembles fragmented messages and serializes masked outbound frames. `websocket.Codec.maxMessageBytes` and `websocket.Session.openWithLimit` accept standard `std.Io.Limit`, with unlimited as the native default. The limit covers full data messages across continuation frames before allocating the next payload; arithmetic overflow is rejected.

`websocket.Session` has one joined reader for its full lifetime, including cached idle periods, and a write mutex shared by request frames and automatic pong/close replies. Active request messages are copied to an owned queue; inactive lease messages are discarded. Request idle timeouts cancel queue waits without interrupting an underlying frame or TLS record. Retain the connection owner through `Session.deinit`, which stops/joins its reader but leaves final transport release to that owner. These native worker/ownership rules require a concurrent allocator and I/O backend. No browser event loop or runtime-specific WebSocket limit is claimed.

Only strictly positive connection and idle timeout values enable their timers; zero, negative and NaN disable them as in the pinned connection/parser code.

Request/response timeout selections dispose late losing results after joining; stream/Models/auth/socket owners join producers and borrowed I/O before releasing arenas or callback contexts. Published partial/final values remain owned by their stream. `durationMs` uses the monotonic awake clock with source rounding, existing-duration and older-message rules; message/diagnostic timestamps, credential expiration and signing dates use wall time. Source SDK wall-clock retry/token bookkeeping is preserved; native sleeps and timeout waits use the awake clock.

Default HTTP no-body responses use an ending reader for HEAD/204/205/304, preserving headers without consuming representation lengths.
